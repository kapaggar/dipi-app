# UI gaps over shipped code — implementation plan (M1–M4)

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** close the four verified UI gaps over already-shipped transport and
parsers — phone sheet viewing (M1), per-student backrest (M2), the duplicate
CW/CH rule (M3), and the Bulk Mail tile retirement (M4) — with zero new
endpoints, zero new query parameters, zero backend change.

**Architecture:** every milestone is presentation-layer only. M1 hoists the
existing `SheetViewerPane` overlay out of the ≥1100dp `DeskHost` to the
`DipiAppUi` root and widens `hubSheetLabel`; M2 threads the already-parsed,
already-persisted `RollRow.backrest` flag onto the four surfaces that draw a
seat; M3 makes `SeatGrid` read the `SeatKind` enum the parser already
produces instead of re-deriving it from the seat string; M4 deletes a tile
with no transport behind it.

**Tech stack:** Kotlin / Jetpack Compose, Robolectric Compose tests in
`:app`, plain JUnit in `:core:*`. No new dependencies.

**Spec:** `docs/handovers/2026-09-05-ui-gaps-handover.md` (source of truth
for this pass), under `AGENTS.md` Hard rules and Current assumptions, which
win over everything including this plan. Visual authority:
`docs/DESIGN.md` + `docs/design/DIPI-Staff.dc.html`.

**Baseline:** `1.38.0` / `versionCode` 63 on `main`, clean tree, full suite
green. Every file:line below was re-verified against this tree on
2026-09-05. Real paths use `src/main/kotlin` (the handover's `src/main/java`
shorthand is wrong; the facts at those files all hold).

## Owner rulings (asked and answered 2026-09-05 — record in `docs/DECISIONS.md` at the end)

- **Q1 (M1 chrome): (a) full chrome, horizontal scroll.** The phone gets the
  same v5 chrome as the tablet — sort segmented control, column chips,
  print, close — with the control band and the sheet body scrolling
  horizontally. M1 is therefore **one slice**, not three.
- **Q2 (M2 marker): chair-back glyph.** Neither `docs/DESIGN.md` nor
  `DIPI-Staff.dc.html` has a per-student backrest treatment (only the
  aggregate counter; `DESIGN.md:368` notes the `BR` seat-span vocabulary).
  Glyph spec below: `⌐` (U+2310), prefix position, with a named fallback
  decision point at hand-verify.
- **Q3 (M4): retire the tile**, and remove the UI code that exists only for
  it. Owner additionally authorized rewriting the tests that pin the tile
  (`CentreScreenTest` ×5 references, `CentreScreenWideTest:196`) to pin the
  retirement instead — the second and last authorized test edit of this pass
  (the first is `CourseHubScreenTest.hubSheetLabelsAreAllDocumentRoutes`,
  pre-authorized in the handover).

## Global constraints (from `AGENTS.md` — every task inherits these)

- No new endpoint, no new POST, no new query parameter, no `@GET` added to
  `StaffApi.kt`. Sheet-GET query allowlist stays exactly `conf` and
  `seating` (`SheetSort.ALLOWED_QUERY_NAMES`). **Never `r` on any sheet

  Server messages verbatim. Retired surfaces stay retired.
- No existing test edited beyond the two authorized above. New test cases

### Glyph spec (owner Q2 ruling: chair-back glyph)

- Glyph: **`⌐` (U+2310)** — a chair-back profile, present in Roboto and
  monochrome-safe.
- Position: **prefix**, one space before the seat id — `⌐ CW-A3` — so the
  right-aligned seat column keeps its right edge and the glyph can never be
  the character the end-ellipsis eats.
- One definition, shared by every surface, in a **new** file so M2 and M3
  stay disjoint in `core:model`:

```kotlin
// core/model/src/main/kotlin/org/dhamma/dipi/staff/model/Backrest.kt
package org.dhamma.dipi.staff.model

/**
 * Per-student backrest marker (owner ruling 2026-09-05). U+2310 — a
 * chair-back profile that survives the monochrome 5i print. Prefix
 * position so the right-aligned seat column keeps its edge.
 */
const val BACKREST_GLYPH = "⌐"

/** `⌐ CW-A3` when [backrest], else the seat unchanged. */
fun backrestSeatLabel(seat: String, backrest: Boolean): String =
    if (backrest && seat.isNotBlank()) "$BACKREST_GLYPH $seat" else seat
```

- **Fallback decision point:** if the glyph renders as tofu on the Pixel C
  (screen or printed page) at hand-verify, swap the constant to `"¬"`
  (U+00AC, guaranteed in every Android font) in this one file and re-run
  W2's scoped tests — assert through the constant, never a hard-coded `⌐`,
  so the swap is a one-line change.
