## 2 · Why the live app differs — the five that matter

These are the explanations, not the task list. Each is cited to a file.

### 1. Five Board chips fetch nothing — every HTML sheet works, every binary fails

`SheetTransport.fetch` splits on `SheetRoutes.of`: HTML goes through
`sheetPage` → `htmlPayload`; binaries go through `sheetDocument` → `save()`
(`core/network/.../StaffApi.kt`). `resolveSheet` then either keeps HTML in
the overlay or, for a document, **closes the viewer** and fires
`DeskUiState.openDoc` (`DeskViewModel.kt`). A `NotAvailable` closes the
viewer and snacks the message verbatim.

The five failing chips are exactly the `SheetRoute.Document` rows:

| Chip | Slug | Server |
|---|---|---|
| Male PDF / Female PDF | `course-pdf-m\|f` | `course_pdf()` in `dipi-web` `inc/course.inc:1265` — calls `generate_course_pdf` then **`s3_get_file(..., 'stream')`**. `$pdf` is unused; the bytes come from S3. Empty/failed S3 still sends `Content-Type: application/pdf`. |
| Day-11 | `report-day11` | `course_day11_report()` (`course.inc:835`) — same S3 stream pattern. |
| Laundry / Valuable | `laundry-list`, `valuable-list` | `dh_laundry_list` / `dh_valuable_list` (`zero-day.inc:3408`) — PhpSpreadsheet writes a temp `.xls`, then `Content-Type:   application/vnd.ms-excel; charset=utf-8` (spaces after the colon, **charset on a binary**) plus `Content-Length`. |

The snackbar **"Could not fetch Laundry list"** is
`SheetTransport.guarded`'s *non-`IOException`* fallback
(`e.message ?: "Could not fetch $label"`). An `IOException` (including
OkHttp's default **10s** read timeout and a `ProtocolException` on a
`Content-Length` mismatch) would have said `Offline — could not reach the
desk for …`. So this is not "no cookie" and not the course — HTML on the
same session succeeds. **Capture an HAR of the five GETs before changing
code.** Ranked hypotheses for the implementer, in order:

1. **S3 miss / empty body** on the three PDFs → `save()` returns
   `"$title came back empty"` *or* a 200 `application/pdf` whose body is
   the S3 error string; the viewer opens and dies (COMPARE: Male PDF
   "Fetching… then closes itself").
2. **`save()` treats `text/html` as a refusal** even on 200. If Drupal
   themes an error, or S3/WAF returns HTML, the snackbar is that HTML
   (or, if `e.message` is null after a parse blow-up, the generic
   "Could not fetch").
3. **OkHttp default timeouts** on PhpSpreadsheet / S3 — would snack
   *Offline…* unless something wraps the timeout.
4. **User-Agent** `DIPI-Staff/1.1 (Android; registrar desk)`
   (`NetworkModule.kt`) — HTML accepts it; a binary path or WAF might
   not. The mock dispatcher never sees this.
5. **After a successful `Document`:** Pixel C has no handler for
   `application/vnd.ms-excel` / `application/pdf`. That path snacks
   *"No app on this device can open …"* (`DipiAppUi.openSheetDocument`)
   — a **different** string. Do not conflate it with (1)–(3).

Mocks (`ExportMockTest`) already pass: they serve tiny fixtures. The
bug is live-only. **Do not "fix" it by sending `?r=` or by adding a
`/staff/*` JSON download.**

### 2. Seating plan **sheet** is an empty grid — the stylesheet hides every seat

`HAR-ROUTES.md` § seating: *"Every cell carries a jQuery-UI
`.ui-state-default` drag handle."* Confirmed in immutable PHP
(`zero-day.inc` `dhBgCell` / `$out .= '<li class="ui-state-default">'`

`course-ops/04` and `08` while the Board sheet is empty.

`SheetViewerTest.injectedStylesheetHidesNoPrintFurniture` **asserts the
string `.ui-state-default` is present** in the CSS. The test must be
retargeted: keep hiding editor chrome (`.dh-add-col`, `.store-seat-changes`,
`.helptext`, `.no-print`, `.drag-img`), **do not hide the seat `<li>`**.

After the cells come back, the page is still the **server's** INI grid
(both genders stacked, leftover JS-dead buttons already hidden) — not
frame `5h`'s designed A–E × 7 native hall with a gender switch.
Owner locked **native 5h on the Board**: reuse the Course ops seating
composable (teacher-at-bottom, letters-as-columns, chowky/chair rail, 66dp
cells, no drag). Still unhide `.ui-state-default` on any leftover HTML path.

### 3. `Master&#039;s` on the Course ops teacher-list sub-line

`TeacherListParser.parseRow` runs education/occupation/languages through
`SearchPageParser.stripTags`. That helper decodes `&nbsp;`, `&amp;`,
`&lt;`, `&gt;` and **stops** — no `&#039;`, `&apos;`, `&quot;`, no
numeric entities (`SearchPageParser.kt`). Drupal emits `&#039;` for an
apostrophe in education text. The Applications list is JSON `dataset`,
so it never hits this path.

Fix in `stripTags` (shared), not a one-off in the teacher-list parser —
every other HTML scrape then stays honest. `HtmlForms.unescape` has the
same hole; close it in the same task if a worker is already there.
Never persist the decoded string beyond the in-memory roll.
