## Binding decisions and corrected assumptions

- Owner clarification: retain the existing confirmation-number eligibility and
  other active statuses. Exclude Cancelled, Left, Rejected, Regret and Duplicate,
  case-insensitively. Do **not** implement the handover's strict
  Confirmed + Expected rule. WaitList stays eligible and is labelled/countable
  separately as held; never silently remove it from the fillable population.
- Preserve finalized Attended historical allocations, read-only Check-in and
  Room Chart, Left exclusion and skipped Zero Day. Calendar dates change Board
  guidance only; they never establish finalization or write attendance.
- Current `deskWide` is **1100dp**, not the handover's 1024dp. Desk shell starts
  at **840dp**; list-detail splitting remains **1100dp**. Under 840dp retain
  the phone flow and root sheet overlay. Course ops is outside this desk pass.
- Scope remains persisted per device. Show the named scope, separate 48dp clear
  and `showing scoped of total`; state each number's population. Rail counts
  remain unscoped. App calculations must be labelled separately from the
  institutional sheets, whose data/exports remain unchanged.
- Existing local Mark attended and room-pull merge semantics remain unchanged.
  Explain local check-in state honestly; do not add an attendance endpoint or
  promise a different conflict-resolution rule.
- The written 14sp text / 48dp interactive-target floor wins over smaller
  examples in the HTML (including 13px audit copy and 44px Calling chips) and
  previous desk measurements. Keep the existing light palettes and use shared
  Steel night roles, not literal dark colours in individual screens.
- ID values are masked initially and revealed only in memory. Reveal state
  must reset on applicant/session changes and leaving the detail; do not use
  saved-state, Room, DataStore, logs or real-data screenshot fixtures.

## Derived semantics and integration contract

1. Compute eligible unscoped roll with the existing non-null conf-number rule
   and five exclusions. Apply gender/seniority through `deskScoped`; unknown
   prefixes retain their existing Both/specific-filter behaviour. Partition
   WaitList for a separate held label/count without losing eligible entries.
2. Every formula must use the same population as its displayed total. For a
   roll subtraction, base is confirmation-eligible rows and excluded means
   only the five statuses within that base; no claim that every removed person
   was Left. Show held as a named subset. Checked-in and remaining partition
   the roll through `deskCheckedIn`, preserving finalized record semantics.
3. Resolve course-name end with `parseCourseWindow` and the existing clock/date
   conventions. Reconcile mode applies on `today == end`; before/after/unknown
   dates do not silently infer a last-day state. Keep finalized mode explicit.
4. On last day, a previously logged phone outcome does not mean someone has
   arrived. Reconcile population is eligible roll minus effective check-ins;
   callable subset requires a phone. Label any difference between remaining
   people and callable people. Use the same base for Board, Calling and rail;
   existing outcome filters and WhatsApp safety/recipient restrictions remain.
5. Audit formulas sum HARD + SAFETY + SOFT occurrences using the same counted
   records. Rail Applications is all applications; Audit is all findings;
   Calling is unscoped remaining call work (or reconcile population labelled
   accordingly); Check-in is unscoped remaining arrivals; Room Chart is actual
   free rooms from inventory minus effective occupied codes.
6. Pane scope denominators name their population. Room availability stays a
   centre/course capacity figure, not a scope-filtered fake capacity. Existing
   server exports and finalized summary handling keep their original meaning.
