**Goal.** Twelve desk sheets arrive from the immutable Drupal desk as print-styled
HTML and render in a hardened WebView with JavaScript off. Every `Columns:` pill,
every `Print` link, the seating drag-and-drop and every in-sheet hyperlink is dead
furniture drawn at the same weight as the data — the seating plan spends ~400dp of
a 900dp screen on an instruction panel about dragging students, none of which
works. This pass removes what cannot work, replaces it with native controls that
can (`?conf=1` / `?seating=1` are ordinary GETs and survive), gives all six HTML
sheets one table style and one header, and moves Course report off the Board onto
the centre dashboard as a native surface. **No new product feature, no new write
protocol, no new endpoint.**

## 1 · Baseline and the SemVer collision — READ THIS FIRST

**Baseline:** `main` = **1.30.5 / versionCode 51**, tip `3560284`. Clean line.

`IMPLEMENT.md` says this pass lands as MINOR **1.31.0 / 52**. **That pair is already
used.** `feat/course-ops` is 21 commits ahead of `main` and has spent both of the
next two pairs:

- `17a2c7e` — *"wire the teacher roll into course ops and ship wave 1 at **1.31.0**"* (versionCode 52)
- `a5a4d1c` — *"…ship wave 2 at **1.32.0**"* (versionCode **53**, the current checkout)

So `feat/course-ops` occupies 1.31.0/52 and 1.32.0/53. The next unused pair on a
single sequential line is **1.33.0 / 54**.

`versionCode` must be unique and monotonic on the device. Two branches that both
claim 52 cannot both reach the Pixel C. **This is an owner decision, not the
implementer's.** Three honest options:

| Option | Branch | Ship as | Holds if… | Risk |
|---|---|---|---|---|
| **A — recommended default** | `feat/sheets-v5` from **`main`** | **1.31.0 / 52** | sheets-v5 merges to `main` **first**, and `feat/course-ops` is rebased and re-bumped (its waves become 1.32.0/53 and 1.33.0/54) before it merges | If course-ops lands or installs first, 52 is a duplicate and the tablet refuses the install |
| B — order-independent | `feat/sheets-v5` from `main` | **1.33.0 / 54** | always | Bakes in the assumption course-ops lands first; leaves 1.31/1.32 owned by an unmerged branch |
| C — leapfrog | `feat/sheets-v5` from `main` | **1.34.0 / 55** | course-ops adds a Wave 3 at 1.33.0/54 | Burns a version for a wave that may not exist |

**Recommendation: Option A.** Branch `feat/sheets-v5` from `main`, ship **1.31.0 /
versionCode 52**, and **leave `feat/course-ops` completely alone** — do not merge
it, do not rebase it, do not touch its files. If the owner would rather not
renumber course-ops later, take Option B (1.33.0 / 54) — it costs nothing but a
version number and is safe in any merge order.

The user's prompt floated **1.34.0**; that figure assumed a further course-ops wave
at 1.33.0. As the tree stands today the sequential-safe pair is 1.33.0 / 54, not
1.34.0 / 55.

**The bump itself is not part of this plan.** Bump `versionName` + `versionCode` in
`app/build.gradle.kts` at integration time, immediately before assembling — never
while only writing docs.

## 2 · Global constraints — verbatim, non-negotiable

- **Never send an `r` query parameter on any sheet GET. Ever.** `?r=1` triggers
  server-side bulk seat auto-allocation and silently reshuffles every student's
  seat. Do not draw, label or imply a regenerate control. **Add a test that fails
  if any sheet GET can be built with an `r` param.** `conf` and `seating` are the
  only new parameters in this pass — keep them an **explicit allowlist**.
- **JavaScript stays off** in the WebView. No cookies, no DOM storage, no
  file/content access. The hardening is deliberate: these pages carry health
  disclosures and contact data.
- **The backend is immutable.** `/Users/wizops/DIPI/dipi-web` is read-only
  reference. No PHP change, no new route, no `/staff/*`, no new endpoint, no new
  JSON contract, no new POST, no CSRF handling beyond the existing form scrape.
- **Server messages verbatim.** Rendered unmodified, including ugly ones like
  `Please Edit application and choose Area teacher before approving!`. No
  rewording, no friendly summary, no icon, no client-side interpretation of a
  status code.
- **No client-side access control anywhere in this app.** Send the request; render
  the answer.
- **No write protocol this pass.** No attendance marking, no seating editor, no
  per-cell room assign, no drag-to-assign, no notes, no photo upload. Status
  writes stay exactly `/change-status/{id}?s=&l=0&c=`; never send `Approved`; no
  status engine in Kotlin.
- **No NPI persisted or logged** — Aadhaar, PAN, passport, voter ID, emergency
  contacts, health disclosures, phone numbers, email. On-screen display for desk
  verification only, via the in-memory `SensitiveInfo` map. **Sheet bodies are
  never persisted:** HTML in memory, documents in `cacheDir/sheets`, wiped on
  logout / session expiry / erase-all.
- **Do not truncate a comment or a health disclosure on print**, and do not hide an
  unanswered or empty field by removing its row.
- **Do not inject the stylesheet in the transport layer** — inject in the UI layer,
  so `SheetPayload.Html` still carries exactly what the server said.
- **Keep the Day-11 chip.** Do not turn it into a 13th grid cell, do not re-propose
  the dashed GAP marker.
- **Status hexes / accent discipline.** Accent means exactly one thing — *live,
  occupied, or selected*. Danger is the fixed pair `#A33A34` light / `#E0796F` dark
  and never follows the skin. No new brand, family, radius or colour outside the
  ladders.
- **Touch targets ≥ 48dp.** Rows 44–52dp, buttons and fields 44–48dp, expander
  glyphs 32dp inside a 48dp target. Nothing below 9sp; no body text below 12.5sp;
  print nothing below 8pt.
- **Retired surfaces stay retired:** Manage Courses, Daily Activity, SMS Report,
  Letters. Do not re-add.
- **Do not commit** `shots/`, HARs, keystores, `local.properties`, or real student
  data.
